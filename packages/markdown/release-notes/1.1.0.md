## @soroush.tech/markdown@1.1.0

### Features

- `LiveEdit` — a preview you write on directly. The document renders exactly like `Preview`,
  split into top-level blocks, and every block is `contentEditable`: type straight into the
  styled output, no textarea. Each input serializes the edited block's DOM back to markdown
  (`rehype-parse` → `rehype-remark` → `remark-stringify`, GFM-aware) and splices it into
  `value`, so `onChange` fires live and untouched blocks keep their exact source. Blur or
  Escape re-splits the document; fenced code keeps its language; ` ```mermaid ` blocks stay
  read-only (a diagram has no text to edit in place). Works standalone (`value`/`onChange`) or
  composed inside a `Control`, and registers the `MarkdownLiveEdit` slot (`root` / `block`) on
  `theme.components` for per-theme styling.

- `Editor` — new `maxRows` prop (forwarded to the underlying auto-grow textarea): the source
  field stops growing at that height and scrolls internally, keeping its border box visible
  inside height-bound panes.

### Fixes

- `Preview` — fenced-code `code` elements keep their `language-*` class on the DOM (previously
  dropped by the styled wrapper). This is what lets `LiveEdit` preserve a fence's language when
  the block is edited in place, and it makes the rendered language targetable by consumer CSS.

### Packaging

- New dependencies for the DOM→markdown pipeline: `unified`, `rehype-parse`, `rehype-remark`,
  and `remark-stringify` (all from the unified ecosystem the package already builds on).

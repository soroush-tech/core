## @soroush.tech/bench@2.3.0

Adds a machine-readable results export, so a CI driver can lay out its own
report from raw numbers instead of the pre-formatted markdown table. The new
flag is optional - omitting it keeps 2.2.3 behavior exactly. (#356)

2.2.4 was never published, so this release also carries its dev-dependency
refresh (see `2.2.4.md`); none of it changes the published tarball.

### Features

- **`--json-file <container-path>` - persist the results as JSON.** Writes
  `{ name, baseline?, cases: [{ label, key, avg, p75, alloc, gc?, ratioPct? }] }`
  to a file (point it inside a writable `--mount`, like `--md-file`). Numbers
  are unformatted (nanoseconds, bytes), there is one entry per case in
  registration order - so a bench comparing three or more packages gets one
  entry each - and `key` is the case label without its `name :: ` prefix.
- **`ratioPct` per case.** With `--baseline-case`, the report names the
  baseline and gives every case its speed as a percentage of the baseline's
  (`baseline.avg / case.avg × 100`) - the same number the `--min-ratio` gate
  checks. The file is written before the gate runs, so a failed run still
  produces it.

### Internal

- The gate and the JSON export now resolve the baseline case through one shared
  helper, so they always agree on which case it is.

### Docs

- README: Options table row for `--json-file`, and the CI-gating example now
  writes it alongside `--md-file`.

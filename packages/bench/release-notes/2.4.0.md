## @soroush.tech/bench@2.4.0

Two additions for reports built from the results: speed ratios without a gate,
and a record of what produced each run. Existing commands behave as before,
except that every run now prints one header line first. (#361, #362)

### Features

- **`--baseline-case` alone reports without gating.** It no longer needs
  `--min-ratio`: the `--json-file` results get `baseline` and each case's
  `ratioPct`, and the run doesn't fail on a slow case. If the key matches no
  case, the run prints a warning listing the case keys and still exits 0. With
  `--min-ratio`, the gate works as before. `--min-ratio` without
  `--baseline-case` is still an error. (#361)
- **What produced a run.** Every run prints a header line, for example
  `soroush-bench 2.4.0 · node v24.22.3 · cpus 1 · cpuset 0 · memory 512m`,
  and `--json-file` records the same facts as `env`. With the base image pinned
  (below), `bench` and `node` together name the sandbox. (#362)

### Changed

- **The sandbox's base image is pinned** as
  `node:24.22.3-slim@sha256:873f586f...`, so a given bench version always builds
  the same sandbox. It was the floating `node:24-slim`, which changed under the
  same bench version. Runs now use Node 24.22.3. (#362)

### Docs

- README: `--baseline-case` documents both uses, the `--json-file` shape
  includes `env`, and two new sections cover reporting without a gate and what
  produced a run.
